# AGENTS.md

## Quick commands

- Frontend commands run from `frontend/`.
- `bun dev` — dev server (uses bun runtime)
- `bun run build` — type-check then build (`vue-tsc -b && vite build`)
- `bun run build-only` — build without type-check
- `bun run type-check` — `vue-tsc --build`
- `bun x biome check --write` — format + lint + organize imports
- Backend commands run from `backend/`.
- `go run ./cmd/api` — start API server
- `go run ./cmd/upload-note -file ../notes/example.md` — signed local Markdown upload
- `go test ./...` — compile and test backend packages

## Tech stack

- Vue 3 (Script Setup), Vite 8, bun, TypeScript ~6.0
- Tailwind CSS v4 (via Vite plugin), Pinia, vue-i18n, GSAP, Three.js
- Go backend with Fx, Gin, Gorm, Supabase PostgreSQL
- Lint/format: Biome (tabs, 4-space, double quotes). No ESLint or Prettier.
- Frontend path alias: `@/` → `frontend/src/`

## Architecture

Monorepo layout: the current Vue portfolio lives under `frontend/`; the Go API lives under `backend/`.

```
frontend/
├── src/
│   ├── main.ts              ← entry, registers plugins, mounts App
│   ├── App.vue              ← wraps DefaultLayout + HomeView
│   ├── config/site.ts       ← configurable profile, skills, projects
│   ├── plugins/             ← pinia + i18n setup
│   ├── stores/              ← pinia stores
│   ├── features/home/       ← Hero, Skills, Works, Contact, ParticleModel
│   ├── components/          ← shared components
│   ├── layouts/             ← DefaultLayout, BlankLayout
│   ├── locales/             ← en.json, zh-hans.json
│   ├── assets/styles/themes/ ← 3 everforest variants
│   ├── types/               ← GENERATED auto-imports.d.ts, components.d.ts — do not edit
│   └── utils/
└── vite.config.ts

backend/
├── cmd/api/main.go
├── internal/
│   ├── app/          ← fx module wiring
│   ├── config/       ← .env loader and typed config
│   ├── db/           ← gorm + postgres
│   ├── http/         ← gin router and middleware
│   ├── markdown/     ← frontmatter, markdown render, sanitize
│   ├── notes/        ← reading notes domain/API
│   └── uploadauth/   ← signed upload middleware
├── migrations/
└── .env.example
```

## Auto-imports (no manual imports needed)

- **Vue APIs**: `ref`, `computed`, `watch`, `onMounted`, `nextTick`, etc.
- **Pinia**: `defineStore`, `storeToRefs`
- **vue-i18n**: `useI18n`
- **Stores**: all from `src/stores/` (e.g., `useThemeStore()`)
- **Components**: all `.vue` files in `src/components/` register globally
- **Icons**: `IconLucide*`, `IconSkillIcons*`, `IconSysIcons*` (prefix: `Icon`)

## Key conventions

- **Pinia stores** use setup-syntax (`defineStore("name", () => { … })`)
- **i18n**: locale persisted as `localStorage("user-locale")`, default `en`, legacy mode off
- **Theme**: dark/light mode + 3 everforest variants (hard, medium, soft). Persisted via `localStorage("theme-mode")` and `localStorage("theme-name")`. CSS classes `dark` and `theme-everforest-<variant>` are applied to `<html>`. Default is everforest-hard.
- **Three.js model**: particle positions pre-computed from OBJ via `cd frontend && bun run precompute`, stored as `frontend/src/assets/particle-positions.json` (777KB). No runtime OBJ download.
- **GSAP**: ScrollTrigger + ScrollToPlugin registered at app level. Scroll animations use `.scroll-section` class convention.
- **Icons**: Custom icons go in `src/assets/icons/` as SVG (collection: `sys-icons`). New icon sets need `bun add -D @iconify-json/<collection>`.
- **Generated files**: `src/types/auto-imports.d.ts` and `src/types/components.d.ts` are auto-generated by unplugin — never edit manually.

## Build & deploy

- `cd frontend && bun run build` requires `vue-tsc -b` to pass first. Unused locals/params will fail the type checker.
- `cd backend && go test ./...` should pass before backend changes are considered done.
- Deploy target is the self-hosted server. Vite base path is `/`.
- CI should run `bun install --frozen-lockfile` from `frontend/`.
